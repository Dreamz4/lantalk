# LanTalk

**LanTalk** is a production-quality, cross-platform LAN messaging application written in C++20. It lets computers on the same Wi-Fi or wired network chat directly with each other — no internet, no cloud, no accounts required.

```
$ lantalk listen
========================================
 LanTalk v1.0.0
 Listening on: 0.0.0.0:5050
 Waiting for peers...
========================================

$ # On another machine:
$ lantalk scan
Found 1 peer:
1. Abhishek
   IP:   192.168.1.42
   Port: 5050

$ lantalk connect 192.168.1.42
========================================
 LanTalk v1.0.0
 Connected to: Abhishek
 Address: 192.168.1.42:5050
========================================

[16:30:10] Abhishek: Hey, this works!
You: It does! 🎉
```

---

## Features

- ✅ **Direct LAN/Wi-Fi messaging** — peer-to-peer, no server
- ✅ **Cross-platform** — Linux, Windows 10/11, macOS
- ✅ **LAN discovery** — `lantalk scan` finds peers automatically via UDP broadcast
- ✅ **Binary framing protocol** — proper message framing, no newline hacks
- ✅ **OpenSSL security** — crypto primitives + HMAC challenge-response auth
- ✅ **Persistent identity** — cryptographically generated device ID on first run
- ✅ **Thread-safe** — concurrent send/receive without blocking UI
- ✅ **Structured logging** — TRACE/DEBUG/INFO/WARN/ERROR levels
- ✅ **Configurable** — INI config in platform-standard location
- ✅ **No runtime deps** — single binary (OpenSSL statically linked in releases)
- ✅ **C++20 / CMake** — clean modular architecture, RAII throughout

## Building from Source

### Prerequisites

| Platform | Requirements |
|----------|-------------|
| Linux    | GCC 11+ or Clang 14+, CMake 3.20+, OpenSSL dev headers |
| Windows  | MSVC 2022 or MinGW-w64, CMake 3.20+, OpenSSL |
| macOS    | Xcode CLT, CMake 3.20+, `brew install openssl` |

### Linux / macOS

```bash
# Install deps (Arch / EndeavourOS)
sudo pacman -S cmake openssl base-devel

# Install deps (Ubuntu / Debian)
sudo apt install cmake libssl-dev build-essential

# Install deps (Fedora)
sudo dnf install cmake openssl-devel gcc-c++

# Install deps (macOS)
brew install cmake openssl

# Build
git clone https://github.com/Dreamz4/lantalk.git
cd lantalk
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
sudo cp build/lantalk /usr/local/bin/   # optional install
```

### Windows (Visual Studio)

```powershell
# Install OpenSSL: https://slproweb.com/products/Win32OpenSSL.html
git clone https://github.com/Dreamz4/lantalk.git
cd lantalk
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --config Release
# Binary: build\Release\lantalk.exe
```

### Windows (MinGW-w64 / MSYS2)

```bash
pacman -S mingw-w64-ucrt-x86_64-gcc mingw-w64-ucrt-x86_64-cmake mingw-w64-ucrt-x86_64-openssl
cmake -S . -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j$(nproc)
```

## Usage

```bash
lantalk --help              # Show all commands
lantalk version             # Show version

lantalk listen              # Start listening on default port 5050
lantalk listen --port 6060  # Custom port

lantalk scan                # Discover LanTalk peers on LAN
lantalk connect 192.168.1.5           # Connect by IP
lantalk connect 192.168.1.5 --port 6060

lantalk config show                   # Show all config
lantalk config set display_name "Bob" # Set your name
lantalk config set listen_port 6060

lantalk status              # Show device ID, name, port
```

### In-session commands (while chatting)

```
/help      — show commands
/peers     — list connected peers
/info      — show local device info
/clear     — clear screen
/quit      — disconnect and exit
/exit      — same as /quit
```

## Configuration

Config is auto-created on first run at:

| Platform | Path |
|----------|------|
| Linux    | `~/.config/lantalk/config.ini` |
| Windows  | `%APPDATA%\LanTalk\config.ini` |
| macOS    | `~/Library/Application Support/LanTalk/config.ini` |

```ini
[identity]
device_id    = <auto-generated UUID>
display_name = YourHostname
platform     = Linux

[network]
listen_port       = 5050
discovery_port    = 5051
max_message_size  = 65536
connect_timeout   = 10

[discovery]
enabled = true

[security]
require_auth = false

[logging]
log_level = INFO
```

## Firewall Configuration

LanTalk uses **TCP port 5050** (chat) and **UDP port 5051** (discovery).

### Linux — ufw
```bash
sudo ufw allow 5050/tcp
sudo ufw allow 5051/udp
```

### Linux — firewalld
```bash
sudo firewall-cmd --permanent --add-port=5050/tcp
sudo firewall-cmd --permanent --add-port=5051/udp
sudo firewall-cmd --reload
```

### Windows Defender Firewall
```powershell
New-NetFirewallRule -DisplayName "LanTalk Chat" -Direction Inbound -Protocol TCP -LocalPort 5050 -Action Allow
New-NetFirewallRule -DisplayName "LanTalk Discovery" -Direction Inbound -Protocol UDP -LocalPort 5051 -Action Allow
```

## Troubleshooting

**Can't connect to peer?**
```bash
# Linux — test TCP connectivity
nc -vz 192.168.1.5 5050

# Windows PowerShell
Test-NetConnection 192.168.1.5 -Port 5050
```

Common causes:
- LanTalk not running on the remote device (`lantalk listen`)
- Firewall blocking port 5050 (see above)
- Both devices not on the same network (some Wi-Fi routers have "client isolation")
- Wrong IP address — use `lantalk scan` to find the right one

**`lantalk scan` finds nothing?**
- Make sure the other device is running `lantalk listen`
- Check that UDP port 5051 is not blocked
- Some Wi-Fi access points block broadcast packets — try a wired connection

## Architecture

```
lantalk/
├── src/
│   ├── main.cpp              — CLI dispatch + lifecycle
│   ├── network/              — TCP socket, server, client, connection, protocol
│   ├── chat/                 — Message, MessageQueue, ChatSession
│   ├── discovery/            — UDP broadcast LAN discovery
│   ├── security/             — OpenSSL crypto + HMAC auth
│   ├── config/               — INI config (platform-aware paths)
│   ├── logging/              — Thread-safe structured logger
│   └── cli/                  — Argument parser + terminal UI
├── tests/                    — Unit tests (no external test framework)
├── docs/                     — protocol.md, architecture.md, security.md
└── .github/workflows/        — CI: Linux + Windows builds, auto-release
```

Wire protocol: `[LTLA magic:4][version:1][type:1][payload_len:4][flags:2][reserved:2][payload]`

See [`docs/protocol.md`](docs/protocol.md) for full protocol documentation.

## Security

- All crypto via **OpenSSL** — no home-grown algorithms
- **HMAC-SHA256** challenge-response authentication (optional PSK mode)
- **Input validation** on all incoming frames — malformed/oversized packets rejected
- **Rate limiting** — peers sending >100 frames/sec are disconnected
- Discovery reveals only: device name, port, platform — no keys or secrets

See [`docs/security.md`](docs/security.md) for the full threat model.
